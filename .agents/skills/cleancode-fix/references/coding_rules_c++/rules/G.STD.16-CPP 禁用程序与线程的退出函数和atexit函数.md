# G.STD.16-CPP 禁用程序与线程的退出函数和atexit函数

- **规则ID**：e341436a-2b77-4ce6-a639-fc1d0de15e24
- **更新时间**：2025-03-25 19:24:11

---

**【问题级别】**

一般

**【描述】**

直接退出进程可能会导致代码的复用性降低，某些资源（尤其是不属于进程的系统资源）在程序退出前难以得到有效地清理。



程序应通过如下的流程结束程序：如程序的模块遇到需要退出的错误时，返回错误码或者抛出异常，当控制流程到上层主控程序函数后，由上层过程处理错误、或捕获它应处理的异常，并释放不再需要的资源后返回；直到返回到main函数，然后由main函数执行退出程序的过程。



因此，本条款实施如下要求：



除main函数以外的其他函数，禁用exit、ExitProcess函数

禁用pthread_exit、ExitThread函数

只有发生致命错误，程序无法继续执行时，可以在错误处理函数中使用abort函数退出程序，其他场景中禁用abort函数。

禁用atexit函数

禁止在线程内主动终止自身线程，线程函数在执行完毕后会自动、安全地退出。主动终止自身线程的操作，不仅导致代码复用性变差，同时容易导致资源泄漏错误。pthread_exit函数将终止调用它的线程，线程终止时不释放任何应用程序可见的进程资源，包括但不限于互斥锁和文件描述符，也不执行任何进程级别的清理操作。windows环境下ExitThread用于使当前正在运行的线程正常停止，运行该函数可能导致主线程退出，而其他线程仍然在执行。停止线程的正确方法是发出干净的退出信号，然后允许线程自行退出，然后再允许主线程退出。



abort()将会导致程序立即退出，资源得不到清理。因为在使用abort()退出程序时，不能保证输入/输出流已经被清空，文件已经正确关闭，或者临时文件已经删除。



使用atexit()有可能导致资源没有被正确的清理：通过atexit()注册的函数须通过return返回，不应调用退出函数（如exit()）或者调用longjmp()等方式返回，否则这些注册函数可能得不到正确执行，还会导致程序产生未定义行为。同时对于所有的退出处理程序来说，程序员应该主动清理不再使用的资源，而不应该在最终程序退出后通过使用atexit()调用事先注册的函数被动地清理资源。

**【正确示例】**

```
正确的做法可以通过错误值传递机制返回上一层调用者。

bool LoadFile(const std::string& fileName)
{
    std::ifstream file(fileName);
    if (file.fail()) {
        ... // 错误处理
        return false;
    }
    ...
    return true;
}

```
**【错误示例】**

```
如下代码中，在文件加载过程中如果出错，直接调用exit退出，可能会造成调用者申请的资源未被清理。

void LoadFile(const std::string& fileName)
{
    std::ifstream file(fileName);
    if (file.fail()) {
        exit(0); // 不符合
    }
    ...
}

```
