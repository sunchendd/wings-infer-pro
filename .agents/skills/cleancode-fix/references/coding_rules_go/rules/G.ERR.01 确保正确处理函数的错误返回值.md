# G.ERR.01 确保正确处理函数的错误返回值

- **规则ID**：a9a0f31f-25a1-444c-a5f5-50ab62fa3230
- **更新时间**：2026-04-07 04:20:02

---

**【问题级别】**

严重

**【描述】**

操作错误，参数错误等是通过返回错误值给调用者进行相应的处理的，如果调用者不处理或者错误处理错误值会导致不可预测的结果。

因此，调用者需确保正确处理函数的错误返回值。

**【正确示例】**

```
##### 场景1：忽略函数的错误返回值。
- 修复示例：正确处理函数的错误返回值。

```go
if b, err = user.Foo(a); err != nil { // 符合：判断错误值并正确处理这个错误
    fmt.Print("Error")
    return
}

// 如果Foo方法存在约定：当此函数返回的错误值 err != nil时，b一定不会为nil。
// 那么如果前面的语句已经判断了无错误，按约定，可直接调用 b.Bar()；否则应判断返回值b有效
b.Bar()
```
##### 场景2：不接收函数的错误返回值。
- 修复示例：正确处理函数的错误返回值。

```go
func foo() error {
    ...
}

func bar() {
    err = foo()
    if err != nil { // 符合：判断错误值并正确处理这个错误
        fmt.Print("Error")
        return
    }
}
```


```
**【错误示例】**

```
##### 场景1：忽略函数的错误返回值。
- 错误示例：

```go
b, _ := user.Foo(a) // 不符合: 忽略错误返回，b可能为nil，从而导致代码运行出错
b.Bar()
```
##### 场景2：不接收函数的错误返回值。
- 错误示例：

```go
func foo() error {
    ...
}

func bar() {
    foo() // 不符合: 不接收错误返回值
}
```


```
**【修复建议】**

增加`error`错误类型的返回值的校验，并且正确处理函数执行失败的情况：`error == nil`表示函数执行成功，`error != nil`表示函数执行失败。
