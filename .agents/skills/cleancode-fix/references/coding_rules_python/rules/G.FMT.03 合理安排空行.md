# G.FMT.03 合理安排空行

- **规则ID**：973d5705-ae97-4e9a-a692-d27fe67549e9
- **更新时间**：2026-04-07 04:15:01

---

**【问题级别】**

一般

**【描述】**

使用空行可以凸显出代码块的相关程度，能提升代码可读性。但是过多的空行并不能带来更多的好处，反而可能降低代码可读性。



可参考如下建议：



1.减少空行，仅在需要特别凸显代码块逻辑分组时使用连续空行，并且最多连续2个空行，比如顶级的类定义或函数定义之间，需要2个空行

2.类中的方法定义之间空一行

3.相对独立的逻辑代码块之间，变量说明之后建议空一行

**【正确示例】**

```
# 【正例1】
def function_name():
    do_something()
# 空行
# 空行
class Example:   # 符合
    …

# 【正例2】
class Animal:
    def eat(self):
        print("Can i eat?")
    # 空行
    def sleep(self):   # 符合，类中的方法定义之间空一行
        print("i want to sleep.")

# 【正例3】
if len(device_name) < MAX_NAME_LEN:
    ...
# 空行
writer = log_writer()

```
**【错误示例】**

```
# 【反例1】
def function_name(): 
    ...
# 空行
# 空行
# 空行
# 空行
class Example:  # 不符合，顶级的函数定义与类定义之间应该空两个空行
    …

# 【反例2】
if len(device_name) < MAX_NAME_LEN: 
    ...
writer = log_writer()   # 不符合，相对独立的程序块之间未加空行

```
**【修复建议】**

1.减少空行，仅在需要特别凸显代码块逻辑分组时使用连续空行，并且最多连续2个空行，比如顶级的类定义或函数定义之间，需要2个空行

2.类中的方法定义之间空一行

3.相对独立的逻辑代码块之间，变量说明之后建议空一行
