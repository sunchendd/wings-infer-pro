# G.DCL.03 变量被使用时才声明并初始化

- **规则ID**：2581ae3b-5ac1-43bc-b82d-6882a0825042
- **更新时间**：2026-04-07 04:20:02

---

**【问题级别】**

提示

**【描述】**

遵循变量作用域最小化原则与就近声明原则，在变量被使用时才声明并初始化，使得代码更容易阅读，方便了解变量的类型和初始值。特别地，尽量使用初始化的方式对变量赋初值。



在函数开始位置声明所有变量，后面才使用变量，作用域覆盖整个函数实现，容易导致如下问题：



- 程序难以理解和维护：变量的定义与使用分离

- 变量难以合理初始化：在函数开始时，经常没有足够的信息进行变量初始化，往往用某个默认的空值(比如零)来初始化，使程序低效，如果变量在被赋于有效值以前被使用，还会导致错误

**【正确示例】**

```
##### 场景1：变量声明与初始化分离，可读性差
- 修复示例1：变量直到被使用时才定义并初始化

  ```go
  // 符合：被使用时才定义并初始化
  var name = "zhangsan"   // 声明并初始化
  msg := "Hello, "        // 声明并初始化
  fmt.Printf("%v%v", msg, name)
  ...
  ```


```
**【错误示例】**

```
##### 场景1：变量声明与初始化分离，可读性差
- 错误示例：

  ```go
  // 不符合：变量声明与初始化相隔代码行过多，可读性差
  var name string   // 声明时未初始化
  var msg string
  ...               // 在此期间未使用name变量
  name = "zhangsan" // 再次调用赋值操作符函数
  msg = "Hello, "
  fmt.Printf("%v%v", msg, name)
  ...
  ```


```
**【修复建议】**

变量直到被使用时才定义并初始化
