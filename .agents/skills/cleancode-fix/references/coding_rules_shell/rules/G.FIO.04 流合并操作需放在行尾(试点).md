# G.FIO.04 流合并操作需放在行尾(试点)

- **规则ID**：639009ad-cabe-4e93-bc87-894b2237959e
- **更新时间**：2025-06-05 04:30:01

---

**【问题级别】**

严重

**【描述】**

流合并操作 2>&1 如果放在一行的中间部分，是无法达到预期效果的，必须放在行尾。

2>&1表示将错误输出合并到标准输出；当然也可以将标准输出合并到错误输出，例如1>&2或>&2，但一般不常用

**【正确示例】**

```
#!/bin/bash

# 期望将错误输出合并到标准输出,然后屏蔽标准输出,放在语句的末尾可以正常生效,不会打印任何输出
rm not_exists.log >/dev/null 2>&1

# 期望将标准输出合并到错误输出,然后屏蔽错误输出,放在语句的末尾可以正常生效,不会打印任何输出
echo abc 2>/dev/null 1>&2

```
**【错误示例】**

```
#!/bin/bash

# 期望将错误输出合并到标准输出,然后屏蔽标准输出,但实际运行还是会打印输出
# 输出告警信息：流合并操作2>&1必须放在尾部才能生效
rm not_exists.log 2>&1 >/dev/null

# 期望将标准输出合并到错误输出,然后屏蔽错误输出,但实际运行还是会打印输出
# 输出告警信息：流合并操作1>&2必须放在尾部才能生效
echo abc 1>&2 2>/dev/null

```
**【修复建议】**

- 将流合并操作(2>&1,1>&2,>&2)放在语句的末尾
