# G.PRE.12 `#if` 或 `#elif` 预处理指令中的常量表达式被求值前应确保其使用的标识符已定义

- **规则ID**：dacbb382-99da-41c3-ba26-d20dc67cc596
- **更新时间**：2026-04-07 04:10:03

---

**【问题级别】**

严重

**【描述】**

如果条件预处理指令中的常量表达式含有编译器不识别的标识符，编译器会将这些标识符替换为常量 0。这是一种实现定义行为，依赖这一行为是不恰当的，甚至可能是遗漏了处理。

因此，良好的做法是在预处理指令中的常量表达式被求值前，使用 #if defined、#ifdef、#ifndef 等预处理指令检查标识符是否已被定义。

**【正确示例】**

```
##### 场景1：在使用前未确保其使用的标识符已定义
- 修复示例：

```c
#if defined(PRE_WLAN_FEATURE_PMF) && defined(PRE_PMF_NOT_SUPPORT) && (PRE_WLAN_FEATURE_PMF != PRE_PMF_NOT_SUPPORT) // 符合
...
#endif
```

```
**【错误示例】**

```
##### 场景1：在使用前未确保其使用的标识符已定义
- 错误示例：

```c
#if (PRE_WLAN_FEATURE_PMF != PRE_PMF_NOT_SUPPORT) // 不符合：在使用前未进行有效性检查
...
#endif
```

```
**【修复建议】**

1. 增加对标识符的检查，确保标识符已定义。

2. 显式定义标识符，并包含该标识符定义所在的头文件。

3. 如果标识符预期必须被定义，但无法通过上下文手段确保的情况，可以通过`#error`的方式尽早显式检查并报告错误。
