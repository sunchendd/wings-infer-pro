# G.PRE.02 定义宏时，要使用完备的括号

- **规则ID**：99fb32e4-17cc-478f-a92b-0a7cb724f7e1
- **更新时间**：2026-04-07 04:10:02

---

**【问题级别】**

严重

**【描述】**

宏展开时只做文本替换，在编译时再求值。文本替换后，宏包含的语句跟调用点代码合并。

合并后的表达式因为操作符的优先级和结合律，可能会导致计算结果跟期望的不同。

因此，在宏定义中，要使用括号确保表达式或语句的正确性。

**【正确示例】**

```
##### 场景1：宏参数未添加括号
- 修复示例：
```c
#define MAX_OF(x, y) (x) > (y) ? (x) : (y)  // 符合
```
##### 场景2：宏参数在赋值语句中未添加括号
- 修复示例：
```c
#define UPDATE_VALUE(value, a, b) (value = (a) + (b))   // 符合：a, b 需要括号；而 value 可以不加括号
```
##### 场景3：宏定义中的负数未添加括号
- 修复示例：
```c
#define ANOTHER_CONST (-1)  // 符合: 负数需要使用括号
```

```
**【错误示例】**

```
##### 场景1：宏参数未添加括号
- 错误示例：
```c
#define MAX_OF(x, y)  x > y ? x : y         // 不符合
```
##### 场景2：宏参数在赋值语句中未添加括号
- 错误示例：
```c
#define UPDATE_VALUE(value, a, b) value = a + b         // 不符合
```
##### 场景3：宏定义中的负数未添加括号
- 错误示例：
```c
#define ANOTHER_CONST -1    // 不符合
```

```
**【修复建议】**

在宏定义中加上括号，如：

```c

#define SQUARE(x) x * x // 不符合

```

改为

```c

#define SQUARE(x) ((x) * (x)) // 符合

```
