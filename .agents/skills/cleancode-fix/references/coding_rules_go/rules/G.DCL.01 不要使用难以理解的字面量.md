# G.DCL.01 不要使用难以理解的字面量

- **规则ID**：86554ad3-dff5-470f-a237-1f3b94c26003
- **更新时间**：2026-04-07 04:20:02

---

**【问题级别】**

一般

**【描述】**

难以理解的字面量是指通过代码的上下文难以明确业务含义的字面量，包括整型字面量、浮点数字面量、布尔字面量和字符串字面量等。



有时候字面量在上下文中是能够理解其含义的，有时候则不能。



例如：`value = 1000;` 不能快速地推断1000表示的含义；但 `millisecond = second * 1000;` 可以很容易理解这里的1000是将秒数转换成毫秒数的比例。要注意此处的millisecond和second的类型是整数，而不是标准库中的time.Duration类型。

**【正确示例】**

```
##### 场景1：使用难以理解的字面量
- 修复示例1：用常量定义字面量，并通过常量名说明字面量含义

  ```go
  // 符合：用常量定义字面量，并通过常量名说明字面量含义
  const WeekHours = 7*24
  totalHours.Add(WeekHours)
  ```
- 修复示例2：用注释说明字面量的含义

  ```go
  // 符合：用注释说明字面量的含义
  totalHours.Add(168) // 一周的时间
  ```


```
**【错误示例】**

```
##### 场景1：使用难以理解的字面量
- 错误示例：

  ```go
  // 不符合：字面量含义难以理解
  totalHours.Add(168)
  ```


```
**【修复建议】**

- 如果某个字面常量经常使用到，在使用的上下文中具有固定的含义，应该定义为常量

- 常量命名应是自注释的

- 对于业务中带有物理量纲的标量类型，建议优先选择标准库中的类型
