# G.INT.10 确保整数转换不会造成数据截断或符号错误

- **规则ID**：a82adb72-3c9c-42c0-b41f-8aef1aea56e9
- **更新时间**：2026-04-07 04:10:01

---

**【问题级别】**

严重

**【描述】**

将整数转换为宽度较小的类型会导致高位被截断，有符号/无符号整数间转换可能导致符号错误。

**【正确示例】**

```
##### 场景1：将整数转换为宽度较小的类型导致数据截断
- 修复示例：首先考虑使用相同的类型

```c
void Foo()
{
    ...
    uint32_t u32 = ...
    uint32_t val = (ret == EOK ? 0 : u32); // 符合
}
```
##### 场景2：有符号/无符号整数间转换导致符号错误
- 修复示例：首先考虑使用相同的类型

```c
void Foo()
{
    ...
    uint32_t u32 = ...
    uint32_t val = (ret == EOK ? 0 : u32); // 符合
}
```


```
**【错误示例】**

```
##### 场景1：将整数转换为宽度较小的类型导致数据截断
- 错误示例：

```c
void Foo()
{
    ...
    uint32_t u32 = ...
    uint8_t u8 = (ret == EOK ? 0 : u32); // 不符合：32位转换为8位，造成截断
}
```
##### 场景2：有符号/无符号整数间转换导致符号错误
- 错误示例：

```c
void Foo()
{
    ...
    uint32_t u32 = ...
    int32_t s32 = (ret == EOK ? 0 : u32); // 不符合：uint32_t转换为int32_t，造成符号错误
}
```


```
**【修复建议】**

1. 先首先考虑使用相同的类型，同时在计算或赋值时要注意不要发生整数溢出或回绕问题。

2. 不要混用有符号数和无符号数。

3. 不要将大类型转化为小类型，除非确保大类型的数值在小类型的上限和下限范围内。

4. 在无法使用相同类型需要转换的情况下，应注意以下几点：

    - 无符号数转无符号数或无符号数转有符号数时，确保数值在目标类型的上限范围内；

    - 有符号数转有符号数或有符号数转无符号数时，确保数值在目标类型的上限和下限范围内。

    - 将整数值转换为具有同符号的更宽类型，能够保证安全地类型转换。
