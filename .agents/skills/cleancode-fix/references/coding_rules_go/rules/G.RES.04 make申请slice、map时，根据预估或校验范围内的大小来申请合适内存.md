# G.RES.04 make申请slice、map时，根据预估或校验范围内的大小来申请合适内存

- **规则ID**：4f201d90-8843-43d3-91e7-51fbf2939c6b
- **更新时间**：2026-04-07 04:20:03

---

**【问题级别】**

严重

**【描述】**

map可以根据新增的<key,value>对进行动态的伸缩，因此它不存在固定长度或者最大限制。map的空间扩展是一个相对复杂的过程，会按一定的规则扩容。对于大的map或者会快速扩张的map，即便只是大概知道容量，也最好先标明。

因此：在初始化slice和map时，根据预估或校验范围的大小来申请合适的容量

**【正确示例】**

```
##### 场景1：在初始化slice时，未正确校验申请的容量，可能导致申请过大容量
- 修复示例：正确判断上下限
    ```go
    func Make_Slice_Map_good2() []int {
        var size1 int
        var s []int
        if size1 > 0 && size1 < 100 {  // 符合：上下限同时判断，合法不告警
            s = make([]int, size1, size1)
        }
        return s
    }
    ```

```
**【错误示例】**

```
##### 场景1：在初始化slice时，未正确校验申请的容量，可能导致申请过大容量
- 错误示例：未判断上限
    ```go
    func Make_Slice_Map_bad1() []int {
        var size uint
        var s []int
        if size > 100 { // 判断下限
            // 没判断上限，不合法，告警
            s = make([]int, size, size)
        }
        return s
    }
    ```

```
**【修复建议】**

在初始化slice和map时，根据预估或校验范围的大小来申请合适的容量
