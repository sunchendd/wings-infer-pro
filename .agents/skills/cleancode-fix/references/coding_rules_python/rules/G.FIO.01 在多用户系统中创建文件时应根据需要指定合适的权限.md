# G.FIO.01 在多用户系统中创建文件时应根据需要指定合适的权限

- **规则ID**：20427a06-c840-411b-aa72-7d1d14af5310
- **更新时间**：2026-04-07 04:15:03

---

**【问题级别】**

严重

**【描述】**

多用户系统中的文件通常归属于一个特定的用户。文件的主人能够指定系统中哪些其他用户能够访问该文件的内容。这些文件系统使用权限和许可模型来保护文件访问。当一个文件被创建时，文件访问许可规定了哪些用户可以访问或者操作这个文件。当一个程序在创建文件时没有对文件的访问许可做足够的限制，攻击者可能在程序修改此文件的访问权限之前对其进行读取或者修改。另外在跨环境场景也有类似问题，需要在创建文件时指定合适的权限。

**【正确示例】**

```
import os
import stat
flags = os.O_WRONLY | os.O_CREAT | os.O_EXCL  # 注意根据具体业务的需要，通过改变os的对应常量来设置相应文件读写方式。
modes = stat.S_IWUSR | stat.S_IRUSR  # 注意根据具体业务的需要设置文件权限
with os.fdopen(os.open('testfile.txt', flags, modes), 'w') as fout:
    fout.write('secrets!')
查看生成的文件，其权限如下所示（只有当前用户有读写权限）：

# ls -l
-rw-------. 1 user  staff   8 May 13 15:04 testfile.txt

```
**【错误示例】**

```
【反例1】
with open('testfile.txt', 'w') as fout:
    fout.write('hi, 2012')

# python内置的open方法无法让程序员显式的指定文件的访问权限。在这个示例中，所创建文件的访问许可取决于具体的环境设置，可能无法防止未授权的访问。
# ls -l testfile.txt
# -rw-r--r--  1 user  staff  8 May 13 15:01 testfile.txt

【反例2】不推荐将文件创建过程与文件权限修改过程分开写。
import os


f = open('my_user_file.txt', 'w')  # 以默认的权限创建文件 -rw-r--r--
...  # 此处包含其他代码，包含一定的时间窗，可能存在条件竞争风险
os.fchmod(f.fileno(), 0o600)  # 修改文件的权限为期望的 -rw-------

【例外】
1、如果文件是创建在一个安全目录中，而且对于非受信用户是不可读的，那么可以允许以默认许可创建文件。
2、如果对文件访问权限无特殊要求，那么可以允许以默认许可创建文件。

```
**【修复建议】**

在多用户系统中可以使用os.open创建文件，根据需要指定合适的权限。
