# G.ERR.04 确保发生异常时程序尝试恢复到合理状态并记录日志

- **规则ID**：531ad97f-a947-43f4-90af-a8f285fb3d81
- **更新时间**：2026-04-07 04:20:03

---

**【问题级别】**

一般

**【描述】**

当函数/方法发生异常时，一般对象需要恢复到原来状态，安全关键的对象则必须恢复到原来状态。保持对象状态一致性的常用手段包括：



1. 输入校验，如校验方法的调用参数。

2. 调整逻辑顺序，使可能发生异常的代码在对象被修改之前执行。

3. 当业务操作失败时进行回滚。

4. 对临时副本对象进行操作，直到操作完成后，才把更新提交到原始对象上。

5. 避免去修改对象状态。



类似空指针引用、越界索引访问等运行时异常发生时，建议将能处理此异常的defer语句放置在goroutine的主调函数中，尝试记录此行为的日志。同时，也可以做些可靠性的设计，必要时可继续将此请求转交给另一个就绪的程序做处理。

**【正确示例】**

```
##### 场景1：在defer-recover恢复机制中忽略发生的异常
- 修复示例：

```go
func process() {
    // 符合：添加defer-recover恢复机制，当存在panic运行时异常，程序将恢复执行
    defer func() {
        if e := recover(); e != nil {
            if re, ok := e.(runtime.Error); ok && re != nil {
                // 尝试为运行时异常做些事情，如：记录日志；做些可靠性的设计，必要时可继续将服务请求交给
                // 另一个就绪的程序做处理 ...
                fmt.Printf("Recover-for-RuntimeError: %v", re)
            } else {
                // 尝试为其他类型的异常做些事情，如继续判断错误的类型，处理特定类型的错误...
                fmt.Printf("Recover-for-No-RuntimeError: %v", e)
            }
        }
    }()
    // ... 特定业务的处理代码
}
```

```
**【错误示例】**

```
##### 场景1：在defer-recover恢复机制中忽略发生的异常
- 错误示例：

```go
func process() {
    defer func() {
        if e := recover(); e != nil {} // 不符合，忽略发生的异常。
    }()
    ... // 特定业务的处理代码
}
```

```
**【修复建议】**

在发生异常时，在defer语句中恢复到合理状态。
