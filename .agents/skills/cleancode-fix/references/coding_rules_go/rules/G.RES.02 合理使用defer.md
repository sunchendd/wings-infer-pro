# G.RES.02 合理使用defer

- **规则ID**：1034e497-3dbf-414d-bc71-3d6a317c6874
- **更新时间**：2026-04-07 04:20:01

---

**【问题级别】**

一般

**【描述】**

不合理地使用defer可能会导致一些问题，如：



1. 堆栈溢出：如果在一个循环中频繁使用defer语句，每次循环都会将一个新的函数调用压入堆栈，如果循环次数过多，可能会导致堆栈溢出。



2. 延迟执行时间过长：如果在defer语句中执行的操作非常耗时，比如进行大量的IO操作或者复杂的计算，那么在函数执行结束前，这些操作都会被延迟执行，可能会导致函数执行时间过长。



3. 内存泄漏：如果在defer语句中使用了匿名函数，并且该匿名函数引用了外部的变量，那么这些变量会被保存在堆上，直到defer语句执行时才会被释放。如果这些变量占用的内存较大，且函数执行时间较长，可能会导致内存泄漏。



4. 代码可读性下降：过度使用defer语句可能会导致代码的可读性下降，特别是在多个defer语句嵌套的情况下，可能会让代码变得难以理解和维护。



因此，在使用defer语句时，需要谨慎考虑其使用场景和频率。

**【正确示例】**

```
##### 场景1：简单场景非必要使用defer
- 修复示例：

  ```go
  var lock sync.Mutex
  var counter int

  func increase() {
     lock.Lock()
     counter++
     lock.Unlock()  // 符合：中间没有过多的异常处理，可以不用引入 defer
  }
  ```


```
**【错误示例】**

```
##### 场景1：简单场景非必要使用defer
- 错误示例：

  ```go
  var lock sync.Mutex
  var counter int

  func increase() {
      lock.Lock()
      defer lock.Unlock()  // 不符合：这里没有必要引入 defer 功能

      counter++
  }
  ```


```
**【修复建议】**

1. 如果函数操作过程简单、无预先退出的分支，没有必要引入 defer 功能。

2. 在defer中修改返回值，会使得代码不易维护，建议不要在defer中修改返回值。

3. 循环中的defer语句，需要函数退出时才会被调用，建议避免在循环中直接使用defer。
