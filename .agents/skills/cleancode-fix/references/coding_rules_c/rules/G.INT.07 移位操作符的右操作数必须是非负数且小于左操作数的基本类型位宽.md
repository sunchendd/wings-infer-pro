# G.INT.07 移位操作符的右操作数必须是非负数且小于左操作数的基本类型位宽

- **规则ID**：4e3a7441-e541-422d-9e6f-df115f6600c9
- **更新时间**：2026-04-07 04:10:04

---

**【问题级别】**

严重

**【描述】**

移位操作（左移或右移）时，如果右操作数的值为负值或者大于/等于整数提升后左操作数的位宽，那么行为是未定义的。



因此，移位操作符的右操作数必须是**非负数**且**小于**整数提升后左操作数的基本类型位宽。

**【正确示例】**

```
##### 场景1：移位操作符的右操作数等于左操作数的基本类型位宽。
- 修复示例1：确保右操作数的值在取值范围内。

```c
uint32_t count = input << 31;           // 符合：右操作数的值是31，满足位宽要求
```
- 修复示例2：整数提升后左操作数为64位无符号整数类型时，右操作数的取值范围是`[0,63]`。

```c
uint32_t input = ...
uint64_t value = (uint64_t)input << 32; // 符合：右操作数的值是32，满足位宽要求
```
##### 场景2：移位操作符的右操作数可能超过左操作数的基本类型位宽。

如果要检查右操作数可能超过左操作位宽的场景，需要在模型中设置 report_maybe 为 true。
- 修复示例：通常要求仅应对无符号操作数执行移位（可参见：[G.INT.05 只能对无符号整数进行位运算]），所以左操作数应为无符号类型，且确保右操作数非负且小于左操作数的基本类型位宽。

```c
uint32_t val = ...
int32_t offset = ...
if (offset <= 0 || offset >= 32) {   // 确保右操作数满足要求
    return val;
}
val = val << offset;                // 符合：满足位宽要求
```


```
**【错误示例】**

```
##### 场景1：移位操作符的右操作数等于左操作数的基本类型位宽。
- 错误示例：当移位操作的左操作数为32位无符号整数类型时，右操作数的取值范围是`[0,31]`，当前右操作数的值超过取值范围。

```c
uint32_t input = ...
uint32_t value = input << 32;           // 不符合：右操作数的值是32，不满足位宽要求
```
##### 场景2：移位操作符的右操作数可能超过左操作数的基本类型位宽。

如果要检查右操作数可能超过左操作位宽的场景，需要在模型中设置 report_maybe 为 true。
- 错误示例：

```c
uint32_t val = ...
int32_t offset = ...
if (offset < 64) {
    return val;
}
val = val << offset;   // 不符合：offset的值有可能大于等于32，不满足位宽要求
```


```
**【修复建议】**

为确保移位操作是正确的，运算结果是符合预期的，要符合以下条件。

1. 移位操作符的右操作数必须是非负数。

2. 移位操作符的右操作数小于左操作数的基本类型位宽，如左操作数是uint8_t类型，右操作数的值要小于8。
