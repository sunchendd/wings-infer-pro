# G.NAM.01 使用统一的命名风格

- **规则ID**：60e6f1c8-ec2f-43aa-9ff1-d8e1b4cfe664
- **更新时间**：2026-04-07 04:20:02

---

**【问题级别】**

提示

**【描述】**

使用驼峰命名风格。具体规则请参照修复建议。

**【正确示例】**

```
##### 场景1：未使用驼峰命名风格
- 修复示例1：按照驼峰命名风格修改

  ```go
  // 符合：结构体和成员命名皆遵照驼峰命名风格
  type tWow struct {
      xDamn int
      url   *url.URL
  }
  ```

```
**【错误示例】**

```
##### 场景1：未使用驼峰命名风格
- 错误示例：

  ```go
  // 不符合：结构体和成员命名未遵照驼峰命名风格
  type t_wow struct {
      x_damn int
      Url    *url.URL
  }
  ```

```
**【修复建议】**

1. 如果项目遵循驼峰命名风格，具体规则如下：



| 类别 | 导出符号 | 包内使用 |

| --------- | ---------- | ---------- |

| 结构体，接口，使用type定义的别名和类型 | 大驼峰 | 小驼峰 |

| 函数，方法（包括结构体的方法，接口的方法） | 大驼峰 | 小驼峰 |

| 结构体成员变量 | 大驼峰 | 小驼峰 |

| 常量 | 大驼峰 | 小驼峰 |

| 全局变量 | 大驼峰 | 小驼峰 |

| 方法接收者，函数参数，返回值，局部变量 |        | 小驼峰 |

| break、continue和goto的标签 |        | 小驼峰 |



2. 如果项目不遵循驼峰命名风格，此规则不适用，建议取消该规则的检查。

- 基于开源或外部代码进行开发或维护时，可以保持原有命名风格

- 本条款未明确要求的标识符命名风格，由项目组自行选择，并保持风格统一
